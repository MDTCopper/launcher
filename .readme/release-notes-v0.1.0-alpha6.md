# v0.1.0 alpha 6 发布 - 接入 Copper 加载器

第二个预览版。这一版把[ **Copper 加载器**](https://github.com/MDTCopper/loader)整条线接了进来（下载 → 启动 → 模组管理），并新增**启动器自身的检查更新**。

> [!warning]
> 当前版本仅发布 Windows 版本。Linux / macOS 的构建与打包链路已写进脚本，但**未在对应系统实测**；Android 端的启动流程尚未开发。

## 新增

### Copper 加载器
- **下载游戏时可以一并选加载器**：下载弹窗里多了一行「启动方式」，可以直接建成 Copper 版本
- **以加载器启动**：走 Copper 的版本用 `java -jar <加载器> -G <游戏本体> -D <数据目录>` 启动，加载器会把核心模组释放到 `copper/mods`
- **加载器库**（数据根下的 `copper_loader/`）：库里已有的直接复用、不重复下载；也可以从仓库下载最新版，或选本地 jar
- **版本兼容标注**：按加载器仓库的适配表（`support.json`）标出「推荐」与「不支持当前游戏版本」，不兼容只提醒、不硬拦
- **两个硬要求**：加载器最低兼容 Mindustry **v146**，并且需要 **Java 17 或更高**（自动选 Java 时会按这个下限挑）
- 加载器文件缺失时能一键「补齐加载器」；启动失败也会说清是「缺加载器」还是「Java / 游戏本体不可用」

### Copper 原生模组
- 模组页能识别 Copper 原生模组（`copper.mod.json`），走加载器的版本会同时管理 `copper/mods` 与 `mods` 两个目录
- 模组条目上标注：`Copper` / `插件` / `依赖` / `冲突` / `不兼容当前游戏版本`
- **`copper-core.jar` 是核心模组**：禁用、删除、全选都会被挡掉并提示
- 导入模组按类型放进对应目录；一个都认不出来的文件只会弹窗提示，不再进到空列表页
- 把 Copper 模组导进非copper加载器的版本时会警告（它们不会生效）；Copper 版本之间新建变体可以继承 Copper 模组

### 启动器自身更新
- 关于页新增「**检查更新**」：查仓库 release、按版本号比大小；下载后安装版覆盖安装，解压版会在退出后自动覆盖并重新打开
- 只做了 Windows；正式版不会收到内测 / 公测版本的更新提示
- **从这个版本起才收得到更新通知** —— alpha 5 及更早的产物里没有这个入口，升级仍需手动下载

## 变动

- **路径改为相对数据根记录**：游戏本体 / 分类目录 / 版本目录 / Java / 加载器都记相对路径，整个数据根搬家、换盘后配置依然可用（老配置不需要迁移）
- **「换启动器新建」**：以当前版本为模板新建一个原版 / Copper 版本
- **内存估算**：走加载器的版本会把两个模组目录都算进去，自动分配内存更准
- 修掉一处网络回包解析问题：查询加载器版本列表偶发失败（`type 'List<dynamic>' is not a subtype of type 'String'`）

> [!note]注意
> - **未做代码签名**：安装包与 exe 会触发 SmartScreen，提示时选「更多信息 → 仍要运行」即可
> - 程序目录里会多一个 **`update.cmd`**：这是更新时用的引导脚本（随版本下发、负责必要的数据迁移），**请不要删**；没有破坏性变更时它什么都不做
> - 数据根目录：解压版就在 exe 旁边（`config.bin` / `versions` / `logs` 都在那里）；安装版在当前用户目录下
> - 预览版，后续版本仍可能有破坏性变更

> [!note] 如何选择 Assets？
> 
> Windows：
> - `copper-launcher-v0.1.0-alpha6-windows-x64.zip` -> 直接解压，双击 exe 即可运行
> - `copper-launcher-v0.1.0-alpha6-windows-x64-setup.exe` -> 双击安装即可使用（按当前用户安装，不需要管理员权限）
>
> 两者可以混用：安装版以后走安装包更新；解压版会在启动器退出后自动覆盖并重新打开。
